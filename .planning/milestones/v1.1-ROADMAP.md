# Milestone v1.1: Client Reports Dashboard (التقارير)

**Status:** ✅ SHIPPED 2026-05-08
**Phases:** 4-6
**Total Plans:** 5

## Overview

Built a comprehensive client-facing reports page (التقارير) in the portal that aggregates all campaign performance data into an analytics dashboard with KPI cards, charts, smart tips, and a sortable campaigns table. Two new aggregate API endpoints, 6 Recharts-based UI components, and RTL Arabic navigation integration.

## Phases

### Phase 4: Backend Aggregates

**Goal:** Client reports data endpoints return accurate, scoped, secure aggregate data for all dashboard widgets
**Depends on:** Phase 3 (client portal UX foundation)
**Plans:** 3 plans

Plans:
- [x] 04-01: Reports API Controller and DTOs
- [x] 04-02: KPI Aggregation Service Methods
- [x] 04-03: Timeline, Top Campaigns, Platform Distribution, and Smart Tips

**Details:**
- `GET /portal/reports` returns composite summary: KPI totals, smart tips, top campaigns list, platform distribution
- `GET /portal/reports/timeline` returns time-series data grouped by month/week/day with Arabic labels
- All aggregate queries scoped to authenticated client's `clientId` — no cross-client leakage
- Empty-state returns well-formed zero-value shapes (not 404)
- Batch snapshot queries avoid N+1 (`campaignId IN (...)` pattern)
- Smart tips generated server-side using rule-based heuristics (4 tips max)
- KPI card aggregates compute SUM of impressions, clicks, conversions, spend
- Period-over-period trend indicators compare current vs. preceding equivalent period
- Donut chart endpoint groups spend by platform with Arabic platform names
- Top performers query returns campaigns sorted by selected metric

**Decisions:**
- Use snapshot.revenue as spend proxy (snapshot has no explicit spend field)
- Period-over-period via equal-length prior window
- Distinct latest snapshot for KPI cards; all snapshots for timeline

### Phase 5: Frontend API + Navigation

**Goal:** `/portal/reports` page is reachable, loads data via RTK Query, and handles all UI states
**Depends on:** Phase 4 (stable API shapes)
**Plans:** 1 plan (integrated)

**Details:**
- "التقارير" link in PortalSidebar between "العقود" and "الفواتير" with BarChart3 icon
- Clicking link navigates to `/portal/reports` which loads and displays report data
- Page shows loading skeletons, error cards, and empty states
- RTK Query endpoints fetch and cache report data with full TypeScript types
- TimeRangeSelector with 3 options: آخر 7 أيام, آخر 30 يوم, آخر 12 شهر

### Phase 6: Charts & Widgets + QA

**Goal:** All dashboard visual components render with real data
**Depends on:** Phase 5 (page shell + API wired)
**Plans:** 1 plan (integrated)

**Details:**
- 4 KPI summary cards: Conversion Rate, Clicks, Impressions, Total Spend — each with ↑/↓ trend
- Monthly comparison bar chart (مقارنة الأداء) with Arabic month labels and metric switcher
- Performance trend line chart (تطور الأداء) with RTL-friendly time axis and area fill
- Spend distribution donut chart (توزيع الإنفاق الإعلاني) with platform breakdown and center total
- Top-performing campaigns table (أفضل الإعلانات أداءً) sortable by any metric
- 4 smart tips cards (توصيات ذكية) with rule-based actionable insights and icons
- Arabic number formatting (compact notation) via Intl.NumberFormat with ar-SA locale
- RTL layout throughout — all charts, cards, and tables render right-to-left correctly
- Responsive layout: cards adapt to screen width
- `turbo build --filter=api --filter=web` passes with zero errors

## Milestone Summary

**Key Decisions:**
- Use snapshot.revenue as spend proxy (no explicit spend field on CampaignKpiSnapshot)
- Period-over-period comparison via equal-length prior window
- Distinct latest snapshot per campaign for KPI cards; all snapshots for timeline
- Default time range "Last 30 days" with day granularity
- Metric switcher on bar/line charts for cross-KPI comparison
- Donut with inner total label (serves as chart + summary stat)
- Sortable table with 3 columns for compact data display

**Issues Resolved:**
- `/portal/reports` was a redirect to `/portal/campaigns` — now fully implemented
- No aggregate endpoints existed for multi-campaign reporting — both endpoints built
- No Recharts components for portal dashboard — 6 widget components built

**Issues Deferred:**
- Export/sharing features (PDF, email scheduling) — deferred to v2
- Custom time range picker (date picker) — deferred to v2
- Campaign health score — deferred to v2
- Drill-down to ad-group/keyword level — deferred indefinitely
- Multi-currency display — deferred indefinitely
- Advanced chart types (funnel, cohort) — deferred indefinitely

**Technical Debt Incurred:**
- snapshot.revenue used as spend proxy — consider adding explicit spend field to CampaignKpiSnapshot in future schema change
- Requirements traceability was never updated during implementation — ensure future milestones keep traceability in sync
