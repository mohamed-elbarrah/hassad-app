# API Error Catalog

The API returns failed requests in the existing compatibility envelope:

```json
{
  "success": false,
  "data": null,
  "error": {
    "code": "CONTRACT_NOT_SIGNED",
    "message": "Contract must be signed before activation",
    "details": null
  }
}
```

`message` is an English fallback for now. Frontends must branch on `error.code`, not message text. `details` is optional and must not contain secrets.

## Conventions

- Codes are uppercase `DOMAIN_REASON` identifiers.
- Codes are stable API contract values; changing copy must not change a code.
- `VALIDATION_FAILED` is used for framework validation arrays.
- Unmigrated HTTP exceptions use status-based fallback codes.
- Domain-specific codes should be added to this catalog in the same change that introduces them.
